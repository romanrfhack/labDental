# Responsabilidades Del Cliente

## Objetivo

Definir las responsabilidades del cliente para que la primera ronda del proyecto Laboratorio Dental Tláhuac pueda validarse, aprobarse y ponerse en producción sin bloqueos operativos.

## Responsabilidades Generales

- Revisar el alcance incluido, opcional y fuera de alcance.
- Aprobar entregables por fase.
- Designar responsables para decisiones de negocio.
- Responder dudas operativas durante la implementación.
- Validar flujos con usuarios clave del laboratorio.
- Confirmar observaciones por escrito o por el canal acordado.
- Separar nuevas solicitudes como cambios de alcance cuando correspondan.

## Materiales Del Sitio Web

El cliente deberá entregar:

- Logo en formato disponible.
- Textos del sitio web.
- Datos de contacto.
- Ubicación.
- Lista de servicios a publicar.
- Horarios de atención, si aplican.
- Fotografías o materiales visuales, si se desean usar.
- Aprobación final del contenido antes de publicación.

Si los textos o materiales no están listos, podrán usarse placeholders únicamente para revisión interna; no deberán considerarse contenido final de producción.

## Dominio Y DNS

El cliente deberá:

- Validar dominio/DNS.
- Proporcionar accesos técnicos cuando sea posible.
- Coordinar cambios con su proveedor de dominio o hosting cuando no pueda compartir accesos.
- Confirmar quién autoriza cambios de DNS.
- Validar que el sitio público cargue correctamente en el dominio acordado.

Los retrasos en dominio/DNS pueden mover la fecha de publicación sin cambiar el alcance funcional.

## Usuarios Clave Y Validación Operativa

El cliente deberá proporcionar usuarios clave para:

- Revisar clientes, doctores y clínicas.
- Validar flujo de órdenes.
- Validar estados operativos.
- Validar pagos, abonos y saldos.
- Validar dashboard básico.
- Validar etiquetas.
- Validar entregas y evidencia.
- Probar demo.
- Confirmar que los flujos representan la operación real del laboratorio.

La validación debe enfocarse en casos reales de negocio, no solo en revisión visual de pantallas.

## Impresión Y Hardware

El cliente deberá:

- Confirmar hardware de impresión.
- Confirmar modelo de impresora.
- Confirmar sistema operativo del equipo que imprimirá.
- Confirmar tamaño y tipo de etiqueta.
- Proporcionar equipo para pruebas cuando se requiera.
- Tener drivers o soporte del proveedor de impresora disponible cuando aplique.
- Validar impresión básica desde navegador.

El servicio local de impresión no queda incluido sin validación previa de hardware, red, sistema operativo, drivers y formato de etiqueta.

## Datos Antes De Producción

Antes de la puesta en producción, el cliente deberá:

- Validar datos de contacto y ubicación.
- Validar datos iniciales que se vayan a cargar manualmente.
- Confirmar usuarios productivos.
- Confirmar credenciales o accesos necesarios.
- Validar cualquier carga parcial de Excel, si se cotiza y aprueba por separado.
- Confirmar que la migración completa del Excel queda como alcance posterior.

El proveedor no asumirá como correctos datos no revisados por el cliente antes de producción.

## Aprobación De Entregables Por Fase

El cliente deberá revisar y aprobar:

| Fase | Responsabilidad del cliente |
| --- | --- |
| Fase 0 - Planeación y documentación | Confirmar alcance, prioridades y exclusiones. |
| Fase 1 - Sistema administrativo MVP | Probar demo administrativa y validar flujos principales. |
| Fase 2 - Sitio web corporativo | Entregar y aprobar logo, textos, contacto, servicios, ubicación y dominio/DNS. |
| Fase 3 - Repartidores y etiquetas | Validar formato de etiqueta, flujo de reparto, hardware de impresión y evidencia de entrega. |
| Fase 4 - QA, capacitación y despliegue | Participar en QA, asistir a capacitación, validar producción y aprobar cierre. |

## Impacto De Retrasos

Pueden impactar fechas o cierre de fase:

- Falta de logo, textos o datos de contacto.
- Cambios tardíos en contenido aprobado.
- Falta de validación de dominio/DNS.
- Falta de usuarios clave.
- Falta de pruebas de demo.
- Falta de confirmación de hardware de impresión.
- Falta de equipo para pruebas.
- Datos no validados antes de producción.
- Solicitudes nuevas tratadas como cambios urgentes.
